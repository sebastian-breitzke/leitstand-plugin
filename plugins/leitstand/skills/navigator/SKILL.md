# Leitstand Navigator

Help Sebastian choose what matters across independent Vorhaben, explore large
ideas and follow through on priorities without loading every chat history.
This entry loads central guidance; it grants no Build-Go or ownership transfer.
Invoke it only for an explicit Navigator request or an accepted split offer.
Mixed topics alone trigger the offer, not this Skill or a chat launch.

1. Use `leitstand:start` to load bootstrap and resolve the Navigator's own
   coordination work and the explicitly selected Vorhaben through actual
   project IDs and supported runtime facts. A title or workspace match is only
   a candidate. Load current `core`, `migration` and `navigator` through
   `leitstand_workflow`; use the MCP Front Door (`tools_search`,
   `tools_describe`, `tools_call`) and its current schemas. Follow bootstrap's
   ownership and migration boundaries before writes or execution; read-only
   Status does not upgrade or register projects.
2. Follow `navigator` for Start, Weiter, Fokus, Status or Aufteilen, using the
   existing intake, questions, state, inspection and orchestration sections
   only where that action needs them. Keep each project's exact workflow pin
   for its storage and task contracts. Reload current guidance on resume or
   compaction; reuse it within the same work phase.
3. Return the relevant result, the decision Sebastian needs now and the next
   step with its responsible owner and evidence pointer. Keep the Navigator's
   own priorities and follow-through centrally; original tasks, questions, Go
   and Delivery stay with their Vorhaben and Kopf.

Report an unavailable connection, project source or client capability precisely.
Preserve pending input in the conversation; never substitute local State,
invent running chats or promise background wakeups.
